# QuickBite — Tài liệu Thiết kế Kiến trúc Frontend

Dự án: QuickBite (Nền tảng đặt & giao đồ ăn)
Kiến trúc Backend: Polyglot Microservices (.NET, Spring Boot, NestJS) giao tiếp qua Kafka.
Kiến trúc Frontend: Tách biệt 2 ứng dụng độc lập (Customer Web và Admin/Merchant Portal) giao tiếp qua API Gateway (NestJS BFF).

---

## 1. Ứng dụng Khách hàng (Customer Web App)

Mục tiêu: Cho phép khách hàng tìm kiếm nhà hàng, xem thực đơn, đặt món, thanh toán và theo dõi đơn hàng realtime. Yêu cầu bắt buộc phải tối ưu SEO cho dữ liệu nhà hàng/món ăn.

### 1.1. Tech Stack
* Framework cốt lõi: Next.js (sử dụng App Router).
* Ngôn ngữ: TypeScript.
* Data Fetching & Caching: Tận dụng Server Components (React Server Components - RSC) của Next.js để fetch dữ liệu từ Catalog Service (danh sách món ăn, nhà hàng) nhằm tối ưu SEO (SSR/SSG).
* Authentication: NextAuth.js (Auth.js) tích hợp với OpenID Connect (OIDC) của Identity Service (.NET ABP).
* Realtime: `socket.io-client` kết nối tới Notification Service (NestJS) để nhận trạng thái đơn hàng realtime (Ví dụ: ORDER_CONFIRMED, DELIVERY_UPDATED).

### 1.2. Chiến lược Deploy
* Nền tảng: Render (Web Service).
* Tính chất: Cần chạy Node.js server ngầm để render HTML cho bot Google (SEO).

## 2. Hệ thống Quản trị (Admin & Merchant Portal)

Mục tiêu: Ứng dụng nội bộ dành cho Chủ quán (Merchant) để quản lý thực đơn, duyệt đơn hàng, quản lý kho nguyên liệu; và Admin quản lý toàn hệ thống. Không cần SEO, ưu tiên tốc độ phản hồi và tính tương tác (Highly Interactive).

### 2.1. Tech Stack
* Framework cốt lõi: React (khởi tạo bằng Vite).
* Ngôn ngữ: TypeScript.
* State Management & Data Fetching: React Query (hoặc SWR) kết hợp Axios. Dùng để gọi API, tự động cache và refetch dữ liệu dashboard ngầm.
* Authentication: Sử dụng standard JWT (Lưu Access Token trong bộ nhớ tạm hoặc HTTP-only cookie, Refresh Token để cấp lại).
* Routing: React Router v6.

### 2.2. Chiến lược Deploy
* Nền tảng: Render (Static Site).
* Tính chất: Trình duyệt tải file tĩnh (HTML, CSS, JS) từ CDN. Hoàn toàn miễn phí, tốc độ cực nhanh, không bị Cold Start (ngủ đông).

## 3. Chiến lược UI/UX & Animation (Áp dụng chung)

Phân tách rõ ràng nhiệm vụ của các thư viện Animation để tối ưu hiệu năng.

### 3.1. UI Components & Micro-interactions (Tailwind CSS)
* Công cụ: Tailwind CSS (kết hợp với Headless UI hoặc Shadcn UI nếu cần).
* Phạm vi: Toàn bộ ứng dụng chính.
* Nhiệm vụ: Xử lý Layout, Typography, và các Animation cơ bản (hover, focus, transition mở menu, spin loading) bằng các class như animate-pulse, animate-spin, animate-ping, transition-all.
* Ưu điểm: Nhẹ, không tốn Javascript runtime.

### 3.2. Màn hình Boot-up / System Health Check (Anime.js)
* Bối cảnh: Do Backend deploy trên Render Free Tier, các microservices sẽ bị "ngủ đông" (Cold Start) mất 30s - 1 phút.
* Giải pháp UX: Xây dựng một component <BootScreen/> chuyên biệt hiển thị sơ đồ kết nối hệ thống.
* Công cụ: animejs.
* Kỹ thuật triển khai:
  - Sử dụng Lazy Loading (`next/dynamic` trong Next.js hoặc `React.lazy` trong Vite) để chỉ tải thư viện Anime.js khi màn hình này xuất hiện, giải phóng bộ nhớ khi Backend đã thức dậy và màn hình này unmount.
  - Kịch bản Animation: Dùng Anime.js vẽ SVG Topology kết nối từ API Gateway ra các service (Identity, Order, Catalog, Payment, Inventory). Nhận tín hiệu Ping từ Gateway (via SSE hoặc WebSocket), service nào báo HTTP 200 thì Anime.js trigger hiệu ứng "Glow/Sáng đèn" cho Node đó trên màn hình.

## 4. Tích hợp Backend (API Gateway & IoT Trigger)

### 4.1. Cổng giao tiếp (BFF - Backend for Frontend)
* Cả 2 ứng dụng FE không bao giờ gọi trực tiếp vào các microservices lẻ.
* Mọi request đều đi qua API Gateway (NestJS). Gateway chịu trách nhiệm gộp dữ liệu (Aggregation), Rate Limit và xác thực JWT.

### 4.2. Kịch bản Wake-up System (Xử lý Cold Start)
* Cung cấp 1 endpoint đặc biệt trên API Gateway: GET /api/system/health/wake-up.
* Khi thiết bị IoT ESP32 (Thiết bị giám sát vật lý) gửi tín hiệu, hoặc khi người dùng mở trang Web, Frontend lập tức gọi endpoint này.
* Gateway sẽ thực hiện Fan-out (gọi song song) đến tất cả các service đằng sau để "đánh thức" chúng, đồng thời trả về trạng thái Realtime cho Frontend cập nhật lên màn hình <BootScreen/> (Anime.js).

## 5. Cấu trúc thư mục tiêu chuẩn (Dành cho AI tham khảo)

### 5.1. Customer Web (Next.js)
customer-web/
├── src/
│   ├── app/                 # App Router (Pages, Layouts)
│   ├── components/          # Reusable components
│   │   ├── BootScreen.tsx   # Lazy-loaded Anime.js loading screen
│   │   └── ui/              # Tailwind/Shadcn components
│   ├── lib/                 # Axios config, Utils
│   ├── hooks/               # Custom hooks (e.g., useSocket)
│   └── types/               # TypeScript interfaces
├── tailwind.config.ts
└── next.config.mjs

### 5.2. Admin Portal (React Vite)
admin-portal/
├── src/
│   ├── assets/              # Images, SVGs
│   ├── components/          # Shared components
│   ├── features/            # Domain-driven feature folders (orders, inventory, catalog)
│   ├── layouts/             # Dashboard layouts
│   ├── pages/               # Route components
│   ├── services/            # API calls (React Query configs)
│   └── store/               # Global state (Zustand/Redux - optional)
├── tailwind.config.js
└── vite.config.ts
